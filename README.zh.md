# Harness 产品插件库

[English](README.md) | 中文

![dsh-file-edit 封面](docs/images/cover.png)

面向 DeepSeek Harness 的产品插件库。当前提供两个插件：**dsh-file-edit** 把资源管理器、文件浏览器与修改审核合成一个文件工作面，在 Harness 里看见每一次文件改动，并就地完成审阅；**dsh-desktop-pet** 是一个住在桌面透明窗口里的伙伴，内置 23 套造型可选，会盯着你的鼠标动、说话时张嘴，并把文字念出来（主推形象**萌妹**的素材由**苍月动漫**提供）。

## 概述

本仓库提供两个可独立启用的产品插件：

| 插件 | 一句话 | 需要你配置什么 |
| --- | --- | --- |
| **dsh-file-edit** | 会话内的文件工作面：改动审核、资源管理器、文件浏览器、文件与选段引用 | 无 |
| **dsh-desktop-pet** | 桌面伙伴：内置角色库、鼠标锁定、说话口型、**朗读文本** | 伙伴自己的方舟接口地址与 模型/TTS/ASR Key；朗读还需**音色 ID**（支持复刻音色） |

### dsh-file-edit：让文件改动看得见

为让 Harness 会话里的文件改动**看得见、改得动、带得走**，该插件在会话内建立统一的文件工作面。

**核心能力**：

- **改动可见**：会话内每一处文件改动进入审核列表，按会话与工作区归属，逐条可接受或拒绝；
- **就地可改**：不离开 Harness 即可打开、编辑并写回工作区文件，Markdown 直接看渲染结果；
- **引用明确**：文件与选段可以引用进对话，模型回答的对象始终清晰；
- **按需收敛**：非常用文件按需隐藏，重要文件可标记并快速定位。

## 功能详情 · dsh-file-edit

### 一、修改审核

**把会话里的文件改动收进一张可操作的列表**：AI 的每一次写入、编辑、删除与移动都进入「修改的文件」。

![修改的文件列表](docs/images/review-list.webp)

- **逐条处置**：每条改动可单独接受或拒绝，顶部支持整批接受与整批拒绝，拒绝后可撤销一层；
- **行级对照**：列表给出新增与删除行数，展开即见行级差异，不必离开会话；
- **删除有隔离**：删除前完整转入持久隔离区，校验失败则禁止删除；拒绝时从隔离区恢复，大文件同样可恢复；
- **删除有墓碑**：同一会话内新建后又被删除的文件显示为「本会话新建后删除」，不会按净零变化凭空消失；
- **目录聚合成行**：完整目录删除在列表里聚合为一行，可展开查看目录内文件，也可整批接受或整批恢复；
- **归属清晰**：子代理产生的改动沿父会话归属，消息编辑派生出的普通子会话保持独立账本；
- **未捕获显式标注**：无法观察到的改动，例如后台 Shell 与未托管兼容 Shell 的写入，会在审核栏的「未捕获」一行具名标出并随会话持久化；
- **快照优先恢复**：重启后先显示持久化待审账本，再校准待审目标的磁盘状态。

### 二、资源管理器

**用工作区文件树接管文件入口**：按工作区展开目录结构，点开即浏览或编辑，替代原生文件侧栏。

![资源管理器与按需隐藏](docs/images/explorer-hide.webp)

- **按需隐藏**：不关心的文件与目录一键隐藏，视图只留常用内容；
- **状态留存**：隐藏、展开与排序偏好按工作区保存，重开 Harness 不必重新整理；
- **官方视觉**：文件与文件夹图标沿用 Harness 官方图标组件，与内核界面观感一致；
- **标签成对**：侧栏标签页自带图标与名称，多个工作区同时打开时不混淆；
- **边界**：跳过 `.git`、`node_modules` 等依赖与缓存目录，树最多 8000 条目、16 层。

### 三、文件浏览器

**在侧栏内完成整篇阅读与编辑**：多标签打开文件，支持语法高亮与整篇编辑，保存即写回工作区。

- **多标签**：文件以标签页并列打开，可切换、可关闭、可拖拽排序，标签状态跨会话保持；
- **批量关闭**：更多菜单提供关闭全部与关闭已处理文件，后者只关已保存且无待审内容的标签；
- **语法高亮**：覆盖 24 种语言与 Markdown；
- **整篇编辑**：编辑器内直接修改并保存，用户编辑折入基线，不打扰 agent 的待审改动；
- **大小边界**：超过 512 KB 或 8000 行的文件转为只读大文件，二进制超过 4 MB 时只保留拒绝与还原；
- **改动定位**：从审核列表点开文件时直接定位到第一处改动并高亮提示。

### 四、文件引用

**把文件与选段带进对话**：在输入框以 `@` 引用文件，或在文档里选中文字后直接引用。

![引用芯片](docs/images/reference-chip.webp)

![选段引用气泡](docs/images/reference-bubble.webp)

- **引用即带位置**：引用芯片显示文件路径与行号范围，模型收到的对象明确到行；
- **选段引用**：在文件或审核视图里选中文字，气泡浮现在选区上方，点击即插入引用；
- **两条通路分工**：差异视图与代码浏览走官方 `@path` 引用，行区间只显示在芯片上；渲染视图的引用把行范围写进文本，而选中行的正文并不发送；
- **与官方一致**：两条通路都声明官方外观，与输入框内其它引用行为统一。
- **气泡可被其它插件扩展**：同一个选段气泡提供注册面，别的插件可以把自己的动作并排加进来（例如桌宠插件的「朗读」），因此两个动作共享一处坐标，而不是两个插件抢同一块位置。

### 五、整体界面

![整体界面](docs/images/app-overview.webp)

- **一个插件三块面**：资源管理器、文件浏览器与修改审核共享同一份会话状态，切换不丢上下文；
- **不抢占原有流程**：没有可浏览文档时浏览器标签自行关闭，会话、对话与轨迹保持原生布局。

### 六、行为与边界

- **审核基准**：整文件接受即当前内容成为新基线；局部接受只结算该片段；局部拒绝把该片段恢复为基线，每次局部操作后重新计算剩余差异；
- **权限归属**：沙箱、审批与权限归内核，本插件只记录变更，不在工具入口否决执行；
- **Shell 记录**：可写工作区的前台 Shell 按执行前快照加递归监听捕获，快照失败不阻止命令执行，会话持久保留部分捕获的结论；
- **修改前内容未知**：`write` 覆盖文件而工具未返回修改前内容时，该行显示「修改前内容未知」，只允许接受或手动处理。

## 功能详情 · dsh-desktop-pet（桌面伙伴）

**一个住在桌面透明窗口里的伙伴**：内置 **19 位伙伴 / 23 套造型**，默认与主推形象是**萌妹**。她会看着你的鼠标动、说话时张嘴，并且能把文字念出来——**朗读文本这个能力就是由本插件带来的**，Harness 内核本身不带朗读。

### 内置角色库

![内置角色库与角色切换](docs/images/pet-library.webp)

- **19 位伙伴、23 套造型**：角色选择器在左侧栏的「桌宠」里，可以按名称搜索，点任意一行即切换并立刻保存；
- **主推形象「萌妹」**：默认选中、排在第一位，也是这款产品的门面角色；她的**素材由「苍月动漫」提供**，我们在此基础上完成 Live2D / 龙骨驱动、鼠标跟随、口型与语音链路（素材权利归其所有者，见文末《来源与致谢》）；
- **一位伙伴多套造型**：同一角色的不同服装合并成一个条目（例如 Mori 的 4 套、户山香澄的 2 套），在角色详情里切换；
- **每个角色独立驱动**：Live2D（Cubism 3/4）与龙骨（DragonBones）角色各自使用自己的动画与互动配置，互不影响。

### 鼠标锁定：视线与身体一起跟

![鼠标锁定后的跟随姿态（一）](docs/images/pet-gaze-1.webp)

![鼠标锁定后的跟随姿态（二）](docs/images/pet-gaze-2.webp)

- **眼球锁定鼠标**：眼球偏移量 18，视线跟着指针走；
- **身体一起跟**：通过官方运行库的 `zhuan` 骨骼叠加偏移驱动身体，位移限制在左右半径 350、上下半径 300 骨架单位的椭圆内，灵敏度 2、0.18 秒平滑，所以跟得动、不抽搐；
- **窗口外也生效**：原生鼠标事件在桌宠窗口之外仍然有效；
- **该回正就回正**：拖拽角色、预览动作、说话、以及角色下方的简洁输入框获得焦点时回正；关闭动画后复位并静止。

### 说话时张嘴

![萌妹说话时张嘴](docs/images/pet-mengmei.webp)

- **按时间轴驱动口型**：Live2D 角色驱动 `ParamMouthOpenY`／`PARAM_MOUTH_OPEN_Y`；龙骨角色使用手工制作的 a／o／i／m 四个口型；
- **先转「读法」再取元音**：阿拉伯数字按中文数字、拉丁字母按字母名、常见符号按读法转写（`%`→百分号、`@`→艾特…），排版类标点只当停顿、闭嘴；
- **不相信不可信的逐字时间**：语音服务对含数字或符号的片段会给固定 30 毫秒跨度，插件改按音频自身的有声片段重排，让嘴只在音频真的停顿时闭合；
- **近似口型**，不宣称音素级对齐。

### 朗读文本

**「把文字念出来」由本插件提供**，四个入口：

- **每条回复的朗读按钮**：在官方回复动作条里，与复制／分享同一排；播放中再按一次就是停止全部朗读；
- **对话里划词朗读**：在对话面板里选中文字，选区上方浮出「朗读」胶囊；
- **选中文档文字朗读**：在文件浏览器里选中文字，浮出的气泡里「朗读」与「@引用」并排——引用来自文件工作面，朗读来自本插件，两个动作共用同一处坐标，谁都不必抢位置；
- **播报主对话**（默认关闭）：把 Harness 主对话里大模型**说给你听的那部分正文**念出来；开关就在**对话标题栏右侧**，喇叭图标区分「声音开启／声音关闭」两种状态。

![在文件浏览器里选中文字后，气泡里「@引用」与「朗读」并排](docs/images/reference-actions.webp)

上面这个气泡就是「选中文档文字朗读」的入口：选一段就念一段，走的仍是「只念人话」的规则，也不会写进桌宠气泡——**气泡只显示伙伴自己的回复**。

### 音色与 Key 需要你自己配置

桌宠有自己独立的一套语音配置（设置 →「对话」／「声音」），**不继承 Harness 的模型设置**：

- **接口与 Key**：填方舟接口地址与模型，并分别填写 模型／TTS／ASR 的 Key；
- **朗读音色**：朗读需要 **TTS Key + 音色 ID**；我们使用的是**豆包语音**（火山方舟）的语音合成接口；
- **支持复刻音色**：把 `S_` 开头的 speaker ID 填进音色即可按克隆音色合成，复刻音色与官方音色走同一套朗读链路；
- **缺什么就说清楚**：没有 TTS Key、没有音色或没有可用的播放窗口时，按钮会直接写明原因，而不是默默失败；
- **朗读是可选的**：不配置 TTS 也能使用角色库、鼠标跟随与文字对话；
- **朗读不依赖桌宠是否显示**：桌宠在屏幕上时由它出声并驱动口型，隐藏时由 Harness 窗口出声（没有口型）；隐藏桌宠不会打断正在念的内容，未播完的片段会交给仍在的窗口继续播。

### 行为与边界

- **伙伴有自己的对话**：右键菜单打开输入框，或使用设置 →「聊天记录」页；两者共用最近一次对话与有上限的上下文，一轮回复固定使用开始时的配置；
- **气泡只属于角色**：主对话正文与朗读内容都不会写进桌宠气泡；
- **模型素材不提交进本仓库**：`desktop-pet/assets/*` 被 `.gitignore` 排除，仓库里只跟踪 `NOTICE.txt`（781 个模型文件在磁盘上、不在 git 里），所以全新克隆有代码但没有模型，需要按 [MAINTAINING.zh.md](MAINTAINING.zh.md) 的步骤恢复；这些素材**会随插件包与产品 Profile 一起交付**，再分发它们需要素材方各自的许可；
- **素材权利归各自所有者**：角色形象、模型与 Live2D Core 的权利不属于本仓库，公开分发前需要各自的许可。

## 安装与启用

两个插件都由 Harness 产品 Profile 装配、随发行包进入运行时：**装好 Harness 就装好了插件，不需要单独的安装脚本**。

- **产品清单**：App 树的 `distribution/profile-manifest.json` 把 `dsh-file-edit` 与 `dsh-desktop-pet` 分别指向 `plugins/file-edit` 与 `plugins/desktop-pet`；
- **会话装配**：App 树的 `distribution/cordis.patch.yml` 插入这两个插件条目；
- **同步**：App 树通过 `npm run sync:plugins` 从本仓库取得插件源码，打包前自动执行；
- **桌宠开箱即用**：角色库、切换角色、摸头与拖动等互动、鼠标跟随都不需要任何配置。桌宠窗口默认不显示，在左侧栏「桌宠」里打开「显示伙伴」即可，这个选择会被记住；
- **需要你自备凭据的只有语音链路**：和角色对话需要桌宠自己的模型接入点与 Key，朗读还需要 TTS Key 与音色 ID（豆包／火山方舟，支持复刻音色）；说话时的口型、字幕与动作关键词都由这条语音链路驱动。这是功能的账号凭据，不是安装步骤，详见上文《音色与 Key 需要你自己配置》。
