# dsh-file-edit

[English](README.md) | 中文

> 本项目全部代码由 DeepSeek-V4-Pro 与 DeepSeek-V4-Flash 生成。

> **本副本说明**：本副本 vendor 自旧统一工程 `harness-macos-desktop-plugin-suite/plugins/file-edit@1.13.43-local`，在新工程中作为产品插件 `dsh-file-edit` 装配，自带权限门禁已整体禁用。它只记录变更供审核，不否决、不拦截任何工具执行：宿主不注册 `tools.guard`，`tools/pre-execute` 一律放行；前台 bash/shell 在可写工作区改为“执行前快照 + 递归监听”捕获（`auditCoverage.kind: partial`）。边界：后台 Shell 放行但不捕获；工作区快照范围之外以及并发外部改动可能记录不到；新内核没有 `shellTransactionLifecycle` 概念，APFS COW 事务路径不再使用；`shell_readonly` 工具保留自身的只读前置检查。下文权限与 Shell 条目已按此语义更新。

DSH WebUI 工作区文件插件，核心功能有两块：

1. **工作区文件浏览与编辑**：文件树浏览、多标签打开、语法高亮、Markdown 渲染，并可在浏览器里直接编辑文件内容；
2. **Diff 视图**：对发生变化的文件展示行级 diff，可逐块或整文件接受/拒绝，拒绝后可撤销。

## 功能

冷会话打开文件只读取 Host 已挂载会话头或持久化会话头，不等待整段对话历史及全量待审核文件水合。客户端传入的 cwd 不作为授权依据；不存在的会话仍拒绝。读取错误不会伪装成二进制下载，切换会话后迟到的打开响应不会切回旧会话。

打开、重复打开或切换文件时，标签栏以 180–250ms 减速动画横向滚动到当前标签刚好可见；已完整可见则不移动，超宽标签对齐开头。快速切换从当前位置转向最新标签，手动滚动、触摸、按键或拖动会中止动画。首次恢复文件视图、切换会话及系统开启“减少动态效果”时直接定位。不移动正文或焦点，也不因审核轮询、输入或拖动排序持续拉回用户滚动位置。

- 文件标签行仅提供文件标签和“更多”菜单；操作区使用独立类名，避免 Message Edit 的旧版消息操作扫描器误插入“编辑消息”和“重试此回合”。

- **权限归属**：AI 调用 `file_delete` / `file_move` 不再由本插件读取 sandbox policy，也不再在工具入口或磁盘修改前拒绝 `read-only` 与工作区外目标；沙箱、审批和权限归内核，本插件只记录变更。用户在文件视图的整文和逐行保存仍限制在当前工作区并保留版本校验及待审核保护。

- **工作区侧边栏**（替换原生浏览器）：项目文件夹两层展开——会话历史（点开会话 / 新建会话；按最近活动时间倒序排列、每行右侧显示「2 min / 1 hr / 1 day」式相对时间标签）与项目文件树（双击/单击打开、手动 ⟳ 刷新、文件集合变化自动刷新）。
- **文件浏览器宿主**：在官方右侧栏可用的运行环境里，浏览器是右侧栏的一个页面型标签——一个标签承载整个浏览器，内部的文档子标签都在这个标签内切换，入口只从 Explorer 的文件点击产生（没有可浏览文档时标签会自己关闭）；此时会话标签条里不再有常驻的「文件」。没有这套侧栏服务的旧产品仍把浏览器挂在会话视图里，与「对话/轨迹」并排。
- **顶栏「文件」标签**：内容区是浏览器式标签条（切换 / ✕ 关闭 / ✕ 全部 / 拖拽排序 / ● 修改标记）。统一打开入口也支持工作区外的普通文本文件：Host 将规范化绝对路径换成不透明 ID，文件以只读方式浏览，不开放整文或逐行编辑。
- **单一文件标题**：文件名只在浏览器式文件标签中显示；内容工具栏不重复标题，Markdown / 编辑中 / 修改等状态标签从左侧起排布。
- **单编辑器引用气泡**：引用由 Harness occurrence/backdrop 绘制，输入始终由原生 textarea 负责，Shift+Enter、中文输入法、删除、撤销和长文本滚动不会因引用存在而切换实现。
- **渲染视图行级引用**：Markdown 渲染视图里选中文本（或按 Command+U）会给出真行号引用 `path:起始行-结束行`，并走插件自己的 ref codec。发送时序列化成官方 `@path` mention 加行范围文字（`@draft.md 第12-19行`），聊天记录因此把它折成官方文件 chip、旁边跟一段短标签，而不是原始标记；**选中行的正文不发送**，模型按范围自己读文件。行号由渲染器自己标注：块级 token 的 `map` 给出块首行，多行段落的 inline 子 token 被 `softbreak` 按源码行切开，所以每个文本片段都能落到确切的一行；围栏代码块逐行标注，表格单元格归到所属行。选区端点落在元素上（三击、拖到块尾）时取该元素内部首/末一个标注，不退化成整块起始行。已知边界：跨行的行内代码会被 markdown-it 折成空格，其后同段文本会落在该代码跨度的起始行（漂移限制在本块内，下一个块级标签重新定位）。
- **两条引用通路的分工**：diff 视图与代码浏览（含它们的 Command+U）走官方 mention `@path`，行区间只出现在 chip 显示名上、模型只得到路径；渲染视图的行引用同样以官方 mention 落进消息，但把行范围写进文本，因为「模型知道我引用了哪几行」是渲染视图引用的目的。两处的输入框 chip 都声明官方 `appearance`，所以都画官方文件图标。
- **修改文件列表**（输入框上方）：会话中经 agent 文件工具（write/edit/file_delete/file_move）产生的修改/新增/删除，带 +/− 统计、逐文件接受/拒绝、全部接受/拒绝、撤销上次拒绝；对话页与文件页统一限制面板高度，文件较多时滚动内容区并保持顶部折叠和批量操作可用。结构化 `file_delete` 可处理工作区内外文件和目录，删除前必须完整转移到持久隔离区，目录中的每个普通文件分别进入同一删除批次的审核账本。
- **审核栏宽度**：与官方输入框卡片同宽——两者都是 `.composerStack` 的子项，而官方卡片处在 16px 侧边距容器里且自身 `width:100%`，所以审核栏取 `min(容器宽 − 2×side-clearance, card-max-width)`，浮层姿态用同一组左右内缩表达。宽度再收窄就放不下地址时先丢掉行内原始地址（完整路径仍留在行的 `title` 上），文件名保留省略号。
- **审核栏墨色**：照官方 dock 卡片与官方文件树的分档——装饰性图元一律用最弱的 `label-tertiary`（领起铅笔、折叠箭头、文件图标），只有标题和文件名留在 `label-primary`，地址行留在 `label-tertiary`；图标钮 hover 升一档到 `label-secondary`，接受/拒绝保留 `state-success`/`state-error` 语义色，只有一处刻意例外：审核绿用插件自己的 `--dsh-fe-review-add`（`#19BB4D`）——官方 success 那一档在审核文案上偏暗——作用于新增行文字与底色、`+` 统计、新增标签与接受图元，取不到该变量时回退 `state-success`。这些规则全部限定在 `.dsh-fe-bar` 内，文件浏览器共用同一批类名，不受影响。
- **图标改用官方那套**：修改文件列表、文件树、删除批次与文件标签统一使用官方文件树与 Explorer 同款的 `FileTypeIcon` 与文件夹图标，经模块表解析（`@deepseek-ai/dsh-client-ui-primitives`，已在 `dsh.client.inject` 声明）；插件不再保留自绘的通用文件/文件夹字形。
- **带行号打开文件**：点修改文件列表里的行会打开该文件并定位到第一个变更；插件把 `dshFileEditOpen`（版本号 1）作为 Cordis 服务提供，其他包用 `ctx.get` 读取并传 `line`/`endLine`，视图把该区间滚进视野并高亮 1.2 秒，编辑视图则改为选中该区间。目标只交付一次，之后的轮询、编辑与手动滚动都不会把位置拉回去。 页面全局 `window.__dshFileEdit` 只作为旧构建的回退保留一个版本，并且只发布有消费方的 `open`。
- **文件标签批量关闭**：标签栏使用固定的三点“更多文件操作”入口，菜单提供“关闭所有文件”和“关闭已处理文件”。后者会先刷新当前会话审核状态，只关闭已经保存、没有待审核内容且没有本地未保存草稿的标签；审核刷新失败时不关闭任何文件。标签滚动区与操作区分离，文件较多时三点按钮和菜单仍保持可见。
- **内联 Diff**：红/绿行级 diff、24 语言语法高亮、块级/文件级接受与拒绝、跳转控件、大文件只读预览、二进制还原。
- **基线制审阅**：整文件接受 = 当前内容成为新基线；局部接受 = 只把该 hunk 结算进基线；局部拒绝 = 只把该 hunk 从磁盘恢复为基线。每次局部操作后都从新的 `base → cur` 重新计算剩余 diff，不持久化顺序型 hunk ID，因此同一文件后续再次被 agent 修改时，已审核内容不会重新出现或误隐藏其他块。整文件拒绝把剩余基线写回磁盘（新增文件拒绝 = 删除文件）；拒绝可撤销（单层）。
- **文件内编辑**：文件视图中直接编辑（contentEditable），用户编辑折入基线、不打扰 agent 的待审 hunks；空文件可直接输入首行。
- **Markdown 渲染视图**：`.md`/`.markdown` 无待审修改时直接渲染（GFM 表格、围栏代码高亮、无行数上限）。
- **事件驱动审核**：write/edit 的完整 before/after 结果会直接写入当前会话账本，包含工作区外的绝对路径文本文件；需要 preset 开启的 `str_replace_editor` 工具，其变更类命令（create/str_replace/insert）以调用前读取的前像与调用后的文件结算；file_delete/file_move 也在执行时直接记账。审核发现不依赖工作区扫描，也不受文件树 8000 项上限影响。
- **子代理审核归属**：`origin: subagent` 会话中的 write/edit/file_delete/file_move 和历史前台 Shell 事件，沿 `parentSession` 归入最近的可见父会话审核栏；消息编辑 Fork 等普通子会话仍保持独立账本，不会被误合并。
- **工作区外安全审核**：外部条目显示规范化绝对路径和“工作区外”标识，接受/拒绝只使用 Host 签发的会话账本 ID；重启后继续保留，拒绝前会校验磁盘版本，避免覆盖其他会话产生的新修改。
- **事务化删除隔离**：`file_delete` 先生成目录清单和持久 `deletionBatchId`，同盘使用原子移动，跨盘使用分块复制、逐文件 SHA-256 校验后再删除原路径；备份或校验失败时禁止删除。顶层符号链接、文件系统根、用户主目录、当前工作区根和审核状态目录不可作为删除目标，目录内符号链接只备份链接本身而不会跟随。被删大文件拒绝时直接从隔离区恢复，不受普通文本/二进制快照大小限制。
- **删除墓碑审核**：同一会话中新建后又删除的文件不会再按净零变化消失，而是明确显示“本会话新建后删除”。墓碑持久化删除来源、批次、时间与目标；接受表示确认文件继续不存在并结束整条变化，拒绝只撤销删除、恢复隔离内容，并继续保留原来的新增审核。修改后删除同理：拒绝删除后，之前的修改仍保持待审核。
- **前台 Shell 审核**：可写工作区的前台 bash/shell/pwsh 统一走“执行前快照 + 递归监听”捕获，命令结束后按工作区签名与候选路径结算新增、修改与删除，并复用现有账本、隔离区和恢复。快照或监听建立失败、事件丢失、范围外写入、瞬时创建后删除以及并发其他进程都可能不被记录或归因，但都不再阻止命令执行。会话持久保留 `auditCoverage.kind: partial`，不宣称全盘可恢复。账本无法捕获的 Shell 入口不再被拒绝，而是如实披露：后台 Shell 调用与未托管兼容 Shell 的调用按会话计数，并在审核栏自己的“未捕获”一行里具名标出，随会话持久化，重启后仍然可见。
- **Shell 修改前快照事务（已停用，不再装配）**：新内核没有 `shellTransactionLifecycle`，这条事务化路径不再使用，前台 Shell 现由上面的“快照 + 监听”捕获，`capturePartialShell` 同样不再使用。原设计为：Host 会完整枚举明确的可写根目录；macOS 对每个根目录执行一次 APFS 递归 COW，失败时在整树容量和剩余空间校验后物理复制，所有载荷仍逐文件通过 SHA-256 验证。紧凑 manifest 以 mtime/ctime/大小等稳定元数据复用未变化文件的哈希，命令结束后生成完整的新增、修改和删除 change set；watcher 只提供候选路径提示。相同或互相包含的工作区事务会串行到持久账本提交完成，不相交工作区可并行。新增和修改进入普通审核，删除从命令前快照转入持久 quarantine，并复用 `deletionBatchId` 的接受、拒绝与整目录恢复。Host 崩溃后遗留的 running/captured 事务会在重新读取审核栏时继续结算；过期准备态与已提交诊断快照仅在后续可写事务或审核恢复时延迟清理，不进入首屏启动路径。
- **外部服务能力正交**：产品 Profile 通过独立、结构化 Host 工具提供受控能力；当前 `dsh-lark-cli` 只开放选定的飞书命令。普通文档创建、更新、导入和上传直接执行；删除、回滚、退出登录和移除访问权限等高风险操作逐次审批。子进程仅可写 lark-cli 状态目录和临时目录，不能修改工作区文件。
- **目录删除批次审核**：完整目录删除在现有审核栏中聚合为单行，与普通文件行统一显示文件夹图标、路径、红色“删除”标签和批次操作；展开箭头紧跟在目录路径后，点击路径或箭头可展开查看目录内文件。展开后的子文件只显示相对路径，不重复显示父目录已经表达的“删除”或“新建后删除”状态。支持接受整个删除批次，或拒绝并从隔离区恢复整个目录，包括空目录和未跟随的符号链接。顶部“全部接受 / 全部拒绝”也会将完整目录作为一个批次处理，不会遗漏空目录、符号链接或隔离区。工作区外批次继续显示“工作区外”并以每个文件原有 opaque ID 打开。若某个子文件已经单独审核，聚合行自动拆回单文件，批次接口也会拒绝部分恢复。
- **外部产物只读浏览**：回答底部产物、正文文件链接、Explorer 与工具结果共用统一打开协议。工作区外普通文件可在「文件」中打开，但目录会被拒绝；浏览 ID 不能用于保存或逐行编辑。若该外部文件已由 AI 修改并进入审核账本，原有接受/拒绝流程继续有效。
- **即时更新**：agent 改/增/删/移动文件后立即唤醒界面，无需等待全工作区扫描或手动刷新。
- **快照优先的启动恢复**：重启后先立即显示持久化待审核账本，再把仅针对待审核目标的磁盘校准提交到 Harness 首绘后的共享串行队列。该调度不会扫描工作区，也不会降低审核强度；切换会话会取消尚未开始的旧校准，已开始请求的迟到结果仍由会话 token 拒绝落地。

## 装配与启用

本插件由 `distribution/profile-manifest.json` 的 `productPlugins`（`dsh-file-edit` → `plugins/file-edit`）装配，随 App 的 Web Profile 一起加载，不需要单独的安装或更新脚本。宿主入口是 `host/index.mjs`，浏览器加载的客户端 bundle 是 `client/dist/client.js`。

## 仓库结构

```
dsh-file-edit/
├── package.json   # dsh.client: { platform: 'web' } + exports["./client"]
├── host/          # Host plugin: session ledger, baselines, diff, accept/reject, JSON-RPC over POST /dsh-file-edit/api
├── client/        # Browser sources; the loaded bundle is client/dist/client.js
└── tests/         # Host and client behavior tests
```

## 运行期数据

- 每会话审阅状态（已结算基线、当前磁盘快照、删除批次关联、撤销记录）存在 `~/.dsh/dsh-file-edit-state/`，由插件自动创建与维护；重启后自动恢复。v7 使用原子替换持久化账本，并兼容读取 v2 至 v6；旧版位置型 hunk decision 仍按 v6 规则迁移。结构化删除和 Shell 删除的原始内容及 `manifest.json` 位于 `<sessionId>/quarantine/<deletionBatchId>/`，未完成的 Shell 生命周期证据位于 `shell-transactions/`。
- 从旧名 `dsh-files` 升级时，宿主首次启动会把旧的 `~/.dsh/dsh-files-state/` 自动迁移过来，待审状态不丢。

## 已知限制

- 替换了原生 WorkspaceBrowser：没有搜索、分组/排序菜单、重命名/删除/归档对话框（保留了添加工作区、打开/新建会话）。
- 跳过目录：`.git` `node_modules` `.venv` `venv` `__pycache__` `.next` `.dsh` `.idea` `.vscode` `.cache` `.turbo` `.pytest_cache` `.mypy_cache` `.ruff_cache` `.eslintcache` `.DS_Store`；树上限 8000 条目 / 16 层。
- 大文件不做行级 diff：>512KB 或 >8000 行标为 `large`（≤512KB 的文本可只读预览前 4000 行）；二进制 ≤4MB 可拒绝还原。
- 前台 Shell 在所有可写模式下都按“快照 + 监听”捕获，在系统权限内执行，不以 `audit_root` 收窄写入。快照不可用、超限或结算失败不阻止命令或重放已经执行的命令；保留原始成功、非零退出或异常。会话持久保留 `auditCoverage.kind: partial`，不显示通用审核不完整文案或标签，也不向 Shell 结果附加这段提示。该记录不单独撑开空审核栏；实际操作错误及具体文件的恢复限制仍保留。移除提示不代表全盘审核完整。后台 Shell 与持久终端已放行，但不被捕获，其改动不进审核账本；这些调用、以及任何未托管兼容 Shell（`powershell`、`shell_command`、`terminal_open`、`terminal_send`）的调用，按会话计数并在审核栏的“未捕获”一行具名标出，列表因此不会被误当成完整证据。`str_replace_editor` 的映射覆盖内核工具定义的变更命令；未开启该工具的 preset 不会产生这类调用。
- 飞书上传等外部服务操作优先使用独立的 `lark_cli` 工具，因为它不经过 Shell 且只能写 lark-cli 状态与临时目录。
- 结构化 `file_delete` 已覆盖文件与目录的事务隔离、删除墓碑和目录批次聚合审核。本插件不约束 Harness 工具流水线中的 AI 工具，也不替代用户在 App 外部或系统终端中的自主文件操作权限。
- `write` 覆盖文件但工具未返回修改前内容时会显示“修改前内容未知”，只能接受或手动处理，不会误报为新增，也不会提供可能破坏数据的自动拒绝。
- 已结算基线和待审状态都会跨插件重启持久化；磁盘若在关闭期间继续变化，打开或审核时仍会按单文件版本校验并要求刷新。
